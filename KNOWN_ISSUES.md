# Known issues

Bugs found in a code review on 2026-10-13 that haven't been fixed yet.
None of them has been reproduced on hardware -- they come from reading the
code, so each one should be confirmed before (or while) fixing it. Remove an
entry in the commit that fixes it.

## Spirograph

### The demo tour can change the curve under a running plot
`src/display/ui_spiro.cpp` -- `SpiroTour::end()`

`end()` restores the visitor's `outside` and `phase` 28s after
`plotFlower()`. If the plot is still streaming then (slow homing, a late
status report), the remaining lines are generated by `rawPoint()` from the
restored globals, and the plotter draws a broken figure. `end()` already
skips `restartPreview()` while a plot is active; it should defer the restore
as well, or the plot should keep its own copy of the curve.

## terraPixel

### Changing the lights' host can push the old device's settings to the new one
`src/net/terrapixel_client.cpp` -- the `hostChangedPending_` block

The host-change reset clears `seededDesired_` but not `setDirty_` or the
desired brightness, radius and film values. If a change was waiting to be
sent, the first request to the new host is a `/set` carrying the old
device's settings, which is what `seededDesired_` exists to prevent.

### "Searching..." hides the real terraPixel status whenever Wi-Fi is down
`src/display/ui_settings.cpp` -- `refreshTpStatus()`

The new `WiFi.status() != WL_CONNECTED` branch wins over the link state,
including in demo mode, where the simulated lights report Connected with no
Wi-Fi. The `else if` there is also mis-indented (it starts at column 0).

## Display

### The big QR animation is heavy (low priority)
`src/display/fancy_qr.cpp` -- `animCb()`

Every 20ms, for the whole 2.3s animation, it redraws every pixel of the
canvas with several `sqrtf` calls and smoothsteps per pixel. That's about
50k pixels a frame on the Knob's 360px panel, on the UI thread, so frames
probably overrun and the knob and touch stall while the QR opens. Caching
module coverage, or redrawing only the modules whose `grow()` changed,
would avoid most of the work. On the Knob it's noticeably laggy but
usable.

### The plot mirror can miss the first stroke of a back-to-back job (low priority)
`src/display/plot_mirror.cpp` -- `startDrawing()`

`startDrawing()` resets the path but not `lastX`/`lastY`/`lastZ`. If the next
job's first report matches the last report of the previous one, it hits the
"no new report" early return and the first segment is never recorded.
The mirror also lags the pen a little; not looked into yet.

## Ideas

### Smooth spirograph plots
`src/display/ui_spiro.cpp`

Plots are straight G1 segments, capped at 3000 points in total, so dense
patterns come out visibly faceted (as few as 3 points a trip round the
ring). Fitting G2/G3 arcs through the points would draw smooth curves from
the same number of lines, or fewer.
